# Account Management System | 账户管理系统

A command-line account management system built with Python and MySQL, featuring CRUD operations, database transaction management, and automated testing with pytest.

基于 Python 和 MySQL 开发的命令行账户管理系统，支持账户增删改查、数据库事务管理以及使用 pytest 进行自动化测试。

## Features | 项目功能

- **View Accounts | 查看账户**
  - Retrieve and display all account records.
  - 查询并显示所有账户信息。

- **Add Account | 添加账户**
  - Create accounts with automatically generated IDs.
  - 创建新账户，由 MySQL 自动生成账户 ID。

- **Update Balance | 修改余额**
  - Update the balance of an existing account.
  - 修改指定账户的余额。

- **Delete Account | 删除账户**
  - Delete accounts after user confirmation.
  - 用户确认后删除指定账户。

- **Error Handling | 异常处理**
  - Handle invalid inputs and database errors.
  - 处理无效输入和数据库操作异常。

- **Transaction Management | 事务管理**
  - Use `commit()` and `rollback()` to manage database transactions.
  - 使用 `commit()` 和 `rollback()` 管理数据库事务。

### 3. Configure MySQL | 配置数据库

Make sure MySQL is installed and running.

确保 MySQL 已安装并正常运行。

Create the application database and table:

创建应用数据库及账户表：

```sql

CREATE TABLE accounts (
    id INT AUTO_INCREMENT PRIMARY KEY,
```

Configure the database connection in `main.py`:

在 `main.py` 中配置数据库连接：

```python

    host="localhost",
    user="root",
    database="index_practice"
)
```

Update the connection parameters according to your local environment.

请根据本地 MySQL 环境修改连接参数。

For security, avoid hardcoding passwords in source code.

出于安全考虑，不建议在源代码中硬编码数据库密码。

## Database Operations | 数据库操作

The project implements four core database functions.

项目实现了四个核心数据库操作函数。

| Function / 函数 | Description / 功能 |
|-----------------|-------------------|
| `view_accounts(conn)` | Retrieve all accounts / 查询全部账户 |
| `add_accounts(conn, name, balance)` | Add a new account / 添加账户 |
| `update_balance(conn, user_id, balance)` | Update account balance / 更新账户余额 |
| `delete_account(conn, user_id)` | Delete an account / 删除账户 |

### Parameterized Queries | 参数化查询

SQL statements use parameterized queries instead of string concatenation.

SQL 语句采用参数化查询，而不是直接拼接用户输入，以降低 SQL 注入风险。

Example / 示例：

```python
cursor.execute(
    "SELECT id FROM accounts WHERE id = %s",
    (user_id,)
)
```

### Transaction Management | 事务管理

Database write operations use transaction management.

数据库写操作使用事务管理机制。

```python
try:
    cursor.execute(...)
    conn.commit()

except mysql.connector.Error:
    conn.rollback()
    raise
```

- `commit()` saves successful operations.
  - `commit()` 提交成功的数据库操作。

- `rollback()` rolls back uncommitted changes when an error occurs.
  - `rollback()` 在发生异常时回滚尚未提交的修改。

- `raise` propagates database exceptions to the caller.
  - `raise` 将数据库异常向外传递，由调用者处理。

Database cursors and connections are managed with `try/finally` to ensure resource cleanup.

使用 `try/finally` 管理 Cursor 和数据库连接，确保资源得到清理。

## Automated Testing | 自动化测试

The project uses pytest for unit testing and integration testing.

项目使用 pytest 完成单元测试和集成测试。

### Unit Testing | 单元测试

Unit tests use `unittest.mock.MagicMock` to simulate database connections without requiring a running MySQL server.

单元测试使用 `unittest.mock.MagicMock` 模拟数据库连接，无需依赖真实 MySQL 服务。

**Test coverage / 测试内容：**

- Querying account records / 查询账户
- Handling empty query results / 处理空查询结果
- Adding accounts / 添加账户
- Handling insertion errors / 处理插入异常
- Updating account balances / 修改账户余额
- Handling nonexistent accounts / 处理不存在的账户
- Deleting accounts / 删除账户
- Verifying SQL calls and transaction operations / 验证 SQL 调用及事务操作

The unit tests also verify:

单元测试还会验证：

- SQL execution parameters / SQL 执行参数
- Function return values / 函数返回值
- `commit()` and `rollback()` calls / 事务提交与回滚
- Cursor cleanup / Cursor 资源清理
- Exception propagation / 异常传播

### Integration Testing | 集成测试

Integration tests connect to a real MySQL database to verify actual database operations.

集成测试连接真实 MySQL 数据库，验证数据库操作是否正确执行。

**Test scenarios / 测试场景：**

1. Insert and retrieve an account / 插入并查询账户
2. Query an empty account table / 查询空账户表
3. Complete account lifecycle / 完整账户生命周期测试

The complete lifecycle test follows this workflow:

完整业务流程如下：

```text
Create Account / 创建账户
          ↓
Read Account / 查询账户
          ↓
Update Balance / 修改余额
          ↓
Verify Update / 验证更新
          ↓
Delete Account / 删除账户
          ↓
Verify Deletion / 验证删除
```

### Test Database | 测试数据库

Integration tests use a separate database to avoid modifying application data.

集成测试使用独立数据库，避免影响应用数据库中的数据。

Create the test database:

创建测试数据库：

```sql
CREATE DATABASE account_management_test;

USE account_management_test;

CREATE TABLE accounts (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    balance DECIMAL(10, 2) NOT NULL
);
```

**Warning / 注意：**

Integration tests delete records from the `accounts` table during test setup and teardown.

集成测试会在测试开始前和结束后清空测试数据库中的 `accounts` 表。

Only run these tests against a dedicated test database containing no important data.

请确保使用专用测试数据库，不要在包含重要数据的数据库中执行这些测试。

The current test setup assumes tests run sequentially and do not share the test table with other processes.

当前测试方案假设测试串行执行，且没有其他进程同时使用测试表。

运行全部测试：

仅运行单元测试：

Run integration tests only:

运行完整账户生命周期测试：
